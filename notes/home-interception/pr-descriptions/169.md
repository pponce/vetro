On my S95C running Tizen 9, selecting the default Samsung Home tile dismissed Vetro's overlay but left the previous app visible. CoBA's `app_launcher` request returned success without displaying Home, so the error-only First Screen fallback never ran.

For the exact `com.samsung.tv.coba.newhome` → `com.samsung.tv.csfs` pair, this change keeps CoBA first and then explicitly opens First Screen even when CoBA returns success. Other app pairs retain error-only fallback, and a csfs-only launch still sends one request. No special setting is required.

This is an isolated two-file change based on post-0.5.0 main `180d9845`. The affected launch path is also present in official v0.5.0 (`81e16b16`). It changes an explicit Samsung Home launch; it does not change normal single-press interception or address the Samsung Home flash discussed in #30. The in-flight close race is covered separately by #117. #151 addresses the related choice of Home target when CoBA and csfs coexist; the approaches should be reviewed together.
