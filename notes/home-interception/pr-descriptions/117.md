Selecting Samsung Home while the launcher's close sequence is still running can open Home and then close it again.

This cancels the remaining scheduled closes and waits for any close command already in progress before launching the requested Home destination. It tracks completion separately for each Home component and uses Ecore's child-process notifications. A timeout or an unrelated child exit is not treated as successful completion.

Related work:
- #55 addresses the same close-guard problem with a shared flag file. This PR handles scheduling and actual child completion inside the launcher.
- #113 handles duplicate delivery of a Home press.
- #169 handles CoBA reporting launch success without displaying Home.
- #30 prevents physical Home from reaching Samsung in the first place. This guard remains relevant when the native fallback path is used.

The branch is based directly on the 0.5.0-based upstream baseline `180d9845`.
