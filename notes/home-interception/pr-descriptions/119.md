Launcher and Remapper need to agree on what the physical Home button should do. This PR exposes one shared Home destination: Samsung Home, toggle the Vetro overlay, or open an installed custom launcher.

The current implementation uses the saved native launcher mode as that assignment. Both editors show the same setting, mode changes are validated, and failed transitions attempt to restore the previous mode. Physical code-63 shortcut rules are reserved for this assignment; older rules remain visible but inactive, and new enabled code-63 rules are rejected.

Samsung Home remains installed and enabled. The current branch still uses the native Home listener and close guard: Samsung can receive Home before Vetro closes its screen. This PR does not currently provide direct Home interception or eliminate the Samsung Home flash.

Direct interception should be coordinated with #30. The shared settings in this PR and the input delivery mechanism need to work together without handling the same press twice. #118 configures the overlay tile; #167 adds double press.

The branch is based directly on the 0.5.0-based upstream baseline `180d9845`, not stacked on those other PRs.

Validation:
- [Current branch CI passed](https://github.com/pponce/vetro/actions/runs/42507788092).
- Tests cover shared mode transitions, validation, rollback, concurrent saves and reserved Home rules.
- The enhanced 0.5.0 build shows Samsung Home briefly before Vetro on my S95C/Tizen 9. Earlier hardware success with an intercepted-Home build should not be treated as validation of this branch's current delivery path.
